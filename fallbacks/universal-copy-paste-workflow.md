# Universal copy-paste workflow

Use this route in a chat system without scripts or file tools.

Fill the studio's existing record shapes with this story. Load the complete `assets/loomfile.template` records and relevant `schemas/` when the host can supply them; preserve their vocabulary, fields and required types while filling the audience, evidence and design. Keep unearned state at its truthful initial value. Arrange the visual plan's `semantic_outline` as a string list of actual reading sections and textual alternatives, alongside its beat-linked representations. Carry one coherent source → claim → story → visual structure through the handoff.

Hand off records a customer can save and resume. Give a file-to-content manifest with each complete source/state/review record and the complete HTML; use the existing template shape rather than reconstructing a smaller record from memory. State the serialization for each path, including one JSON object per line for journals, and preserve the initializer's actual identity/timestamps when applying project fields. Re-entry supplies execution and evidence to the authored records. When their contract resources are unavailable, label the result a planning package and name the resources needed for a complete Loomfile handoff.

1. Create a source table with stable ids, titles, supplied dates, authority, and locators.
2. Create a claim table with stable ids, exact wording, source id, locator, as-of date, currentness, and status.
3. Build a 5–9 beat story spine with a named tension, turn, payoff, analytical arc, and emotional arc.
4. Choose prose, diagram, chart, interaction, or omission for each beat and explain why the evidence earns that form.
5. Produce one complete semantic HTML document in a fenced code block. Keep all essential meaning available without JavaScript and avoid external dependencies.
6. If requested, produce a 6–14 panel carousel as a panel-by-panel package with copy, visual direction, claim ids, source note, alt text, and transition purpose.
7. Produce a diagnostic record: top three corrections, secondary findings, unresolved claims, currentness limits, human approvals, and unproved evidence layers.
8. Give exact filenames and later commands for initializing, inspecting, validating, and packaging in a normal Signal Loom Infographics installation.

For a later correction, retain the original file contents and old assessment, label the revised work draft, and show which evidence and visible values change together. Without tools, leave current review-basis capture and byte comparisons unexecuted; do not invent digests or claim format 0.2.0 reviewed/approved consistency. The later command is `python scripts/migrate_loomfile.py ORIGINAL NEW_COPY`; then follow `docs/STATE-AND-REVIEW.md`.

Never split a file across multiple alternatives. Never claim that copied text was executed, rendered, parsed, tested, or packaged.
